# Campus Data Manager

A Next.js App Router application for viewing and managing students, courses, and library books. The interface uses the starter's shadcn Base UI components and neutral theme.

## Run locally

Requires Node.js 22.13 or newer and pnpm. Node.js 22 emits an experimental warning for its built-in SQLite module.

```sh
pnpm install
pnpm dev
```

Open http://localhost:3000. The three databases are created and seeded on first use. You can also initialise them explicitly:

```sh
pnpm db:seed
```

The seed command is repeatable. It preserves existing edits and does not restore deleted records.

| File               | Sample records | Fields                                    |
| ------------------ | -------------- | ----------------------------------------- |
| `data/students.db` | 15 students    | ID, name, email, programme, study year    |
| `data/courses.db`  | 12 courses     | ID, course code, title, credits, lecturer |
| `data/library.db`  | 20 books       | ID, title, author, ISBN, available copies |

Every file has an independent SQLite connection. Records persist across server restarts. Set the server environment variable `CAMPUS_DATA_DIR` to use another writable directory. Database files are excluded from Git.

## Interface

Select a database from the sidebar. Search across its fields, filter by programme, lecturer, or author, and sort using the column headers. Tables show ten records per page. Add and edit dialogs validate fields before submitting; the server independently validates every request. Deleting a record requires confirmation.

Student emails, course codes, and ISBNs are unique. Emails and course codes are case insensitive. ISBNs accept 10 or 13 characters and strip spaces and hyphens. Study years range from 1 to 8; credits from 1 to 60; available copies from 0 to 10,000. IDs are generated by SQLite.

The layout supports mobile navigation, horizontal table scrolling, keyboard controls, and light/dark themes. The selected database is retained in the URL.

## API

Each collection supports `GET` and `POST`. Each record supports `PUT` and `DELETE` at its ID URL.

- `/api/students` and `/api/students/:id`
- `/api/courses` and `/api/courses/:id`
- `/api/library` and `/api/library/:id`

`GET` returns `{ records: [...] }`; successful writes return `{ record: {...} }`. Validation failures return status 400, duplicate values 409, and missing records 404. Successful deletes return 204. Incoming JSON uses the field names in [lib/records.ts](lib/records.ts).

## Verify

```sh
pnpm test
pnpm typecheck
pnpm lint
pnpm build
pnpm start
```

Database tests use a temporary directory. They exercise CRUD, constraints, isolation, connection reopening, and seeding in a separate process without changing local app data.

This first version is a local demo without authentication. A hosted version needs access control and a persistent writable volume for SQLite; ephemeral serverless storage cannot retain these files reliably.
